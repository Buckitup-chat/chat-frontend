# Аудит стека Community Sharing Backup & Recovery — сентябрь 2026

Отчёт фазы «code review + security audit по всем модулям». Метод: шесть
контекстно-независимых аудиторов (по осям), каждая нетривиальная находка
доказана исполнением (hardhat/jest/vitest-пробы, локальные экземпляры ноды,
read-only пробы живого прода). База: июльские снапшоты репозиториев
`Community-secret-sharing/*` (совпадают с задеплоенным продом — проверено
health/bytecode) и текущий `chat-frontend`. Тесты всех модулей зелёные до и
после (контракты 62, SDK 15, клиент 517).

Сокращения: C/H/M/L = critical/high/medium/low.

## Критичные и высокие — полный список

### Нода (`backitup-node`)
- **N-C1. Депозит fail-open при ошибке RPC** — `ownerOnChain` глотает любую
  ошибку как «секрета нет on-chain» → приём **без подписи**; DoS RPC =
  окно на перезапись любого шара мусором (подтверждено исполнением).
  Фикс: различать `SecretDoesNotExist` и транспортные ошибки; на вторых —
  отказ (503), никогда не безаутентификационная ветка.
- **N-C2. Подпись депозита не покрывает байты шара** и не содержит nonce и
  node-id → реплей перехваченного владельческого запроса с подменённым
  телом, на все три ноды. Фикс: в сообщение — hash(share) + nonce + nodeId.
- **N-H1. Pre-chain окно**: до майнинга AddSecret депозит без подписи, а
  overwrite-правило пускает равные/большие версии → отравление + локаут
  легитимного v1 (409 «stale»). Фикс: подпись владельца всегда.
- **N-H2. Нет замка на overwrite при активном восстановлении** → «вето
  порчей»: владелец (или N-C2-атакующий) корёжит свой шар посреди раунда.
  Фикс: депозит отклоняется при `recoveryActive`.
- **N-H3. Release-запрос**: GET с подписью в URL (логи/Referer), реплей без
  ограничений весь час (дефолт 3600с при документированных 300), `Math.abs`
  принимает будущие ts. Фикс: nonce/однократность, POST, `age<0` → отказ,
  nodeId в сообщении.

### Клиент (`chat-frontend`, backup/testbed)
- **F-C1. Local File без KDF**: ключ Blowfish = срез сырых байт пароля
  (для 10-символьного — последние **2 символа**), IV = первые 8 символов
  открыто, без соли и MAC (доказано пробой). Фикс: PBKDF2-SHA-256 ≥600k
  (или Argon2id) → AES-256-GCM, версионированный заголовок файла.
- **F-H1. Shamir-шары = сырые фрагменты незашифрованного JSON ключей**,
  выдаются копипастом → история клипборда одной машины собирает все n шаров.
  Фикс: конверт (случайный ключ AES-GCM, делится только ключ) + заголовок
  шара (версия/id/чексумма) + выдача файлами.
- **F-H2. Тестстенд в прод-роутере** с кнопками против живых Sepolia/relayer.
  Фикс: за dev-флагом.
- **F-H3. Приватные ключи и payload плейнтекстом в localStorage** без
  очистки (`testbed.guardians`, `testbed.backups`). Фикс: не хранить, wipe
  на logout.
- **F-H4. Сломанная stealth-математика в `buckitup.js`**: деривация
  приватного ключа сложением при умножении в адресе → адреса не сходятся
  (доказано), восстановление этим путём невозможно.

### Relayer (`backitup-recovery-backend`)
- **R-H1. Нет rate-limit/квот/gas-cap** на 9 неаутентифицированных
  relay-эндпоинтах → дренаж газа диспетчера одноразовыми EOA.
- **R-H2. TOCTOU preflight→send без дедупликации** → N параллельных копий
  одного payload'а: N−1 ревертов за счёт диспетчера; self-front-run.
- (M) Поля без MaxLength → атакующий выбирает стоимость транзакции;
  `/notifications?wallet=` отдаёт **Telegram chat-id владельца** любому
  (подтверждено на проде); подписка бота без доказательства владения =
  слежка за восстановлениями; индексер без reorg-отката.

### Контракты (Sepolia, требуют v2-деплоя)
- **K-H1. Стейл-подписи `*WithSig` как «откат»**: прямые вызовы не сжигают
  nonce → удержанная/ревертнутая подпись reshare живёт до неограниченного
  дедлайна и **переустанавливает выселенного скомпрометированного
  хранителя** (доказано); в KeyRegistry — откат на скомпрометированный
  мета-адрес; cancel-подпись не привязана к раунду. Фикс: version в
  `Reshare`, round в `CancelRecovery`, публичная инвалидация nonce, кап
  дедлайна.
- (M) **Один скомпрометированный хранитель навсегда пинит `recoveryActive`**
  и блокирует собственное выселение (T4-защита threat model опровергнута;
  SI-4 — обязательный, не «улучшение»). Фикс: owner-reshare неявно
  сбрасывает раунд.
- (M) **`canDecrypt` не истекает** (true и через 10 лет — T9/SI-2 подтверждён).
- (M) Liveness-клин пост-кворума: потеря избранного получателя = соцполовина
  навсегда (см. вопрос В11 обзора).
- (M) `revokeSecret` посреди раунда без `RecoveryCancelled` → дрейф
  проекции индексера (лечится на бэкенде сегодня).

### SDK (`backitup-secret-recovery-sdk`)
- **S-H1. Роли spending/viewing перепутаны**: внутри SDK две перестановки
  взаимогасятся (golden-вектор пиннит это), клиентский testbed — наоборот →
  кросс-реализационные шары молча невосстановимы. Канон выбирать против
  продакшн-векторов; починка одной из двух перестановок осиротит бэкапы.
- (M) `hexToBytes`: NaN→0 — мусорный hex превращается в нулевой «секрет»
  (обе половины равны); `threshold=1` допускается (одиночный хранитель =
  вся половина); `recoverSecret` без целостности — одна злая нода → тихо
  неверный K.

### Сквозные наблюдения
- **Три несовместимые stealth-реализации** (SDK / buckitup.js / testbed):
  compressed- против uncompressed-хеширования адреса, add против multiply.
  Канон — одна реализация в SDK, клиенты импортируют.
- Testbed-network-режим **не реализует** схему RFC: шары нод возвращаются
  плейнтекстом (без шифрования на эфемерный ключ), XOR-делится случайный K,
  а сам payload лежит рядом в localStorage — Vernam-слой ничего не защищает.
- Дрейф параметров RFC↔прод↔testbed сведён в таблицу C клиентского отчёта.
- Threat model контрактов: T4/T6/T10 сформулированы неверно (опровергнуто
  исполнением), SI-2/SI-4 переквалифицированы из «улучшений» в обязательные.

## Чистое (важнейшее из «checked and clean»)

- Криптоядро SDK: XOR (CSPRNG, длины), Шамир, ECIES (MAC/IV), stealth-CDH,
  **инъективная** деривация secret-id (standard-ABI).
- Контракты: EIP-712-хеширование (вкл. массивы структур), кворум-учёт,
  таймлок-границы, доступ на каждой внешней функции, отсутствие
  реентерабельности; KeyRegistry чист.
- Relayer: авторизация как таковая — контрактная (подпись+nonce+deadline
  проверяются над теми же байтами); ключ диспетчера не течёт.
- Нода: release-гейт fail-closed по `canDecrypt`; шары не пишутся в логи.
- Клиент: RNG возле ключей — только CSPRNG; console.log ключей нет.

   кап дедлайна), SI-4 (reshare сбрасывает раунд / cooldown), SI-2 (окно

4. **SDK**: канон stealth-ролей (после сверки с продакшн-векторами),
